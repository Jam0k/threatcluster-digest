## Vulnerabilities

### [PHP Session File Flaw phpAfterShell (CVE-2026-126714) Enables Unauthenticated RCE](https://threatcluster.io/cluster/php-session-file-flaw-phpaftershell-cve-2026-126714-enables--ae3cec8c)

On 19 November 2026 the PHP project released coordinated builds for PHP 8.2 through 8.6 closing 17 security advisories, seven rated critical at CVSS v4.0 9.2. The headline flaw, phpAfterShell (CVE-2026-126714), lies in PHP's default file-based session handler, where a partially overwritten session file can be spliced so that a later session_start() deserialises attacker-chosen objects. MyCERT reports that chained with a memory-corruption bug in a PHP-native class, this becomes remote code execution in the web worker, typically www-data. The flaw sits in PHP itself rather than in any application or framework, so any stack keeping sessions in files is in scope until PHP is upgraded. MyCERT describes phpAfterShell as a descendant of PHP2Shell (CVE-2026-109618/109619, October 2026), and states that servers patched for PHP2Shell remain vulnerable. Red Hat's bulletin RHSB-2026-020 lists CVE-2026-126714 and related flaws as critical and notes that its fixes are being expedited. As of 21 November 2026, MyCERT reports no in-the-wild exploitation of phpAfterShell and the seven critical CVEs are not in CISA KEV, though a full public exploitation chain has been described by the discoverer, depthfirst. Red Hat's investigation is described as ongoing.

### [Upload2Shell: Ghostscript Type 1 Font Loader Flaw Enables Command Execution (CVE-2026-125396)](https://threatcluster.io/cluster/upload2shell-ghostscript-type-1-font-loader-flaw-enables-com-c4b30294)

Researchers disclosed Upload2Shell, a use-after-free in Ghostscript's Type 1 font loader that lets a crafted document escape the -dSAFER sandbox and execute attacker-chosen commands as the rendering process, per the Hacker News post by pwn.ai. The flaw is tracked as CVE-2026-125396 (CVSS 8.5) and affects upstream Ghostscript releases before 10.08.0. The researchers say the bug is reachable through routine document, image, email, upload and preview workflows, including files named .png or .jpg passed through ImageMagick conversion. Cybersecuritynews reports that WordPress, Roundcube webmail and Linux print servers could be reached this way without exposing Ghostscript directly. The researchers say WordPress Core's upload path exposed the renderer to Author-level users and Contributors granted upload_files, and that several plugins had public upload fields requiring no login; WordPress shipped a separate fix, CVE-2026-65640. The researchers filed the flaw upstream with Artifex (Bug 709684), and Artifex released Ghostscript 10.08.0 with the fix on 2026-09-08. Debian packaged the release and later issued a Debian 13 security update; the articles also mention a confirmed unauthenticated CUPS path on Debian 13 whose details were cut off in the source.

*2 sources · score 58 · CVE-2026-125396, CVE-2026-65640, Upload2Shell*
